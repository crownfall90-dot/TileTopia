### 2.6. Исправление автообновления тестовой версии (Staging APK Auto-Update)
- **Проблема, обнаруженная у пользователя:**
  Пользователь сообщил: *"в тестовой версии после обновления мне еще не пришло обнова"*.
- **Причина расследования:**
  В `.github/workflows/staging.yml` версия `versionCode` вычислялась как `CODE=$(( ${LAST:-260} + 1 ))`. Поскольку `LAST` брался из тегов `v*` (релизы продакшена, последний был `v261`), значение `CODE` всегда оставалось равным `262`. Внутренний механизм обновления `Updater.java` проверяет `f.getInt("code") <= BuildConfig.VERSION_CODE`. Поскольку 262 <= 262, он считал, что сборка актуальна, и не предлагал обновление. Кроме того, ОС Android отказывается устанавливать поверх APK с одинаковым или меньшим `versionCode`.
- **Решение:**
  В `.github/workflows/staging.yml` добавлен автоматический инкремент версии: скрипт запрашивает код предыдущей тестовой сборки из `latest-staging.json` и увеличивает его на 1 (`PREV_STAGING + 1`). Теперь при каждом пуше код версии строго растёт (262 → 263 → 264...), и телефон пользователя мгновенно обнаруживает новое обновление при запуске или нажатии «Проверить обновления».

## 📂 3. Карта ключевых файлов проекта

| Файл / Папка | Назначение |
|---|---|
| `web/game.html` | Основная разметка и логика игры: инициализация экранов, Canvas-рендер фигур, контроллер реакций, контроллер инбокса, вызовы `show(...)`. |
| `src/main.js` | Главный бандл ES-модулей: экспорт `ui`, `game`, `account`, `net`, `render`. |
| `src/ui/inbox.js` | Модуль инбокса: список уведомлений, расчёт бейджа, рендеринг карточек. |
| `src/state/catalog.js` | Каталог фигурок (`FIGS`), рамок (`FRAMES`), сундуков (`CHEST_SVG`, `CHEST_OPEN_SVG`), локаций (`LOCS`). |
| `src/ui/shop.js` | Витрина магазина, логика колоды реакций (`renderItemsEmotesHtml`, `ALL_EMOTES`, `ALL_PHRASES`). |
| `src/ui/styles.css` | Стили интерфейса, анимации рамок (`@keyframes`), стили инбокса, скрытие тумана войны. |
| `app/src/main/assets/index.html` | Автогенерируемый скомпилированный HTML для Android-приложения (создаётся через `tools/wrap_web.py`). |
| `build/web/index.html` | Скомпилированный Web/PWA файл. |
| `tools/wrap_web.py` | Скрипт сборки через Vite и упаковки в один монолитный HTML-файл для WebView. |
| `tools/export-tiles.html` | Интерактивный симулятор стыковки 3D-плиток (4 стороны и 6 сторон) и векторных плиток. |
| `assets/tiles/` | Папка со спрайтами PNG 512×512 и ZIP-архивами диорамных плиток. |
| `.github/workflows/staging.yml` | CI/CD для сборки тестового APK (`Tiletopia Test`), публикации в пре-релиз `staging-latest` и генерации `latest-staging.json`. |

## 🧪 4. Как проверять и собирать проект

```bash
# 1. Запуск юнит-тестов (все 212 тестов должны быть зелеными):
node --test tests/*.test.cjs

# 2. Пересборка монолитных HTML файлов (после правок в src/ или web/):
python tools/wrap_web.py

gh run list --limit 3
gh release view staging-latest
```
