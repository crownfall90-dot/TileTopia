Репозиторий: D:\TileTopia (Tiletopia, игра-пазл с плитками в стиле Каркассона, веб + Android WebView). Сначала прочитай CLAUDE.md, docs/design/STYLE.md, assets/tiles/README.md, src/engine/tiles.js и tools/blender_generators/generate_tiles.py.

ЦЕЛЬ
Сделать для ВСЕХ плиток игры два согласованных набора из одного источника:
  1) 3D-модели плиток (детализированные, низкополигональные, пригодные для игры);
  2) 2D-спрайты 512×512, отрендеренные из этих же 3D-моделей, чтобы 2D и 3D выглядели одинаково.

ЧТО УЖЕ ЕСТЬ
- src/engine/tiles.js: словарь TYPES. Стороны N E S W: c город, r дорога, w река, f поле, b половина большого моста, x обрыв. Плюс редкие плитки x*, которые генерируются кодом. Движок трогать нельзя: tests/golden.test.cjs переигрывает записанные партии.
- assets/tiles/tile_*.png: плоские спрайты 512×512 (по README их 37). Это эталон по содержанию и стилю.
- assets/tiles/classic_4side и hex_6side, tile_4s_*.png и tile_6s_*.png: только по 9 диорам на набор.
- assets/tiles/classic_4side_defs.json и hex_6side_defs.json: описания плиток. Читай их как UTF-8.
- tools/blender_generators/generate_tiles.py: существующий генератор. Расширь его, не пиши с нуля.
- Blender 5.2.3 установлен в D:\Blender\blender.exe. Аддон MCP стоит. Если сервер не отвечает, запусти Blender и нажми Start MCP Server.
- Poly Haven включён галочкой сцены blendermcp_use_polyhaven, она действует только на текущий .blend. После перезапуска включи заново.

ЗАДАЧИ
1. Описания плиток: один источник правды (JSON) со всеми типами из TYPES, включая редкие x*. Для каждой плитки: id, стороны, особые элементы (город, монастырь, мост, шахта, валуны, обрыв, крепость).
2. 3D-генератор в Blender (bpy), параметрический и запускаемый из командной строки:
   blender -b -P tools/blender_generators/generate_tiles.py -- --set classic
   Классика 4 стороны. Затем набор hex 6 сторон, по той же схеме. Единый масштаб, начало координат в центре основания, ось Z вверх, чтобы плитки стыковались без зазоров. Элементы строить процедурно: дороги, река, стены города, здания, деревья, мост, шахта, валуны, обрыв. Для текстур камня, травы и воды брать Poly Haven.
3. Экспорт: каждая плитка в GLB (assets/tiles3d/<set>/<id>.glb). Целевой размер: до 5k треугольников на плитку, материалы без лишних текстур, чтобы грузилось на слабых телефонах.
4. 2D-рендер: из тех же сцен 512×512 PNG с прозрачным фоном, один и тот же ракурс (изометрия) и одно освещение для всех плиток. Кладём в assets/tiles/ под прежними именами, чтобы игра не ломалась. Старые файлы перезаписываем только после сравнения с эталоном.
5. Проверка: обязательно смотри результат через mcp__blender__look и сравнивай с эталонными PNG. Скрипт проверки: все id из TYPES имеют .glb и .png; у соседних сторон нет зазоров; размеры и число треугольников в пределах бюджета.
6. Интеграция в игру: сначала только подготовь данные. Не переписывай game.html целиком, это монолит (см. docs/product/MONOLITH-PLAN.md). 3D-режим в интерфейсе делай отдельным шагом после того, как плитки готовы.

КЛЮЧИ И ВНЕШНИЕ СЕРВИСЫ
Работай без платных сервисов. Poly Pizza, Sketchfab и генераторы моделей (Tripo, Meshy и др.) пока не трогай. Я добавлю ключи позже. Сделай так, чтобы ключи были необязательными: читай их из переменных окружения (POLYPIZZA_API_KEY, SKETCHFAB_TOKEN) или из настроек аддона Blender MCP. Никогда не клади ключи в репозиторий и не печатай их в ответах. Если ключа нет, используй процедурные модели.
