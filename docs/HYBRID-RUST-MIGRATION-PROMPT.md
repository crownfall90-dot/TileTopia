Реализовать их на Rust в `crates/tiletopia-core/src/grid.rs` и `crates/tiletopia-core/src/tile.rs`.

### 👉 ШАГ 3: Валидатор ходов и графовый подсчет очков
Реализовать:
- `validator.rs`: мгновенная проверка, можно ли поставить тайл `T` с поворотом `rot` в координату `(q, r)` (совпадение типов сторон всех существующих соседей).
- `graph.rs` & `scoring.rs`: обход графа (BFS/DFS) для поиска замкнутых дорог, замкнутых стен городов, проверка закрытия монастырей (8 соседей) и мажоритарности миплов.

В `crates/tiletopia-core/src/bot/` реализовать генератор ходов и алгоритм Monte Carlo Tree Search. За 10–20 мс бот должен симулировать сотни вариантов и выбирать стратегически сильный ход.

## 🧭 Архитектурная философия: Почему именно гибридный подход?

В Tiletopia уже создан кинематографичный мобильный UI:
- **Современный CSS3**: физика ленты главного меню 1:1 в стиле Clash Royale, 60 FPS замедления `cubic-bezier(0.22, 1, 0.36, 1)`, пружинящий микро-отскок (`bnavPop`), глубокий стиль королевского обсидиана, эффекты матового стекла (`backdrop-filter: blur`), примерка баннеров в реальном времени.
- **Мгновенные обновления по воздуху (OTA)**: при обновлении логики или визуала игра обновляется на устройствах за 1 секунду по сети без необходимости скачивать и заново переустанавливать 50-мегабайтный APK.
- **Ультралегкий бандл для Web и Telegram Mini App**: игра весит всего ~250 КБ (gzip) и мгновенно стартует даже на слабых устройствах.

**Принцип гибридной архитектуры**:
Выносим в **Rust (WebAssembly)** исключительно тяжелые математические алгоритмы и ИИ-симуляции, сохраняя весь визуал, анимации, адаптивную верстку и сетевые протоколы на **JavaScript/CSS3**.

## 🎯 Цели и ключевые результаты (KPI)

1. **Скорость ИИ-бота (AI Bot)**:
   - Переход от примитивной жадной эвристики 1-го хода к глубокому поиску по дереву (Monte Carlo Tree Search / Alpha-Beta Minimax) с глубиной просчёта на 3–5 ходов.
   - Время принятия решения ботом сложности «Гроссмейстер»: **менее 20 миллисекунд** на ход.
2. **Нулевые просадки FPS (Off-Main-Thread)**:
   - Вычисления ИИ-бота и поиск замкнутых контуров выполняются в фоновом **Web Worker** либо через квантованные микро-задачи, гарантируя стабильные 60–120 FPS анимаций на основном потоке.
3. **Размер бинарного файла WebAssembly**:
   - Размер оптимизированного `.wasm` модуля (после `wasm-opt -Oz`): **не более 45–60 КБ**.
4. **100% надёжность и прозрачный Fallback (Graceful Degradation)**:
   - Если WebAssembly не поддерживается средой или ещё не загрузился, игра прозрачно использует существующий JS-движок (`src/engine/`). Никаких белых экранов и сбоев.
5. **Работа в локальном Android WebView (`file://`)**:
   - Поддержка встраивания Wasm-модуля через Base64/TypedArray для полного обхода ограничений CORS на протоколе `file:///android_asset/`.

## 📐 Архитектура Rust-ядра (`crates/tiletopia-core`)

### 1. `Cargo.toml`
```toml
[package]
name = "tiletopia-core"
version = "1.0.0"
edition = "2021"
authors = ["crownfall <crownfall90@gmail.com>"]
description = "Высокопроизводительное математическое и ИИ ядро для Tiletopia"

[lib]
crate-type = ["cdylib", "rlib"]

[dependencies]
wasm-bindgen = "0.2"
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"

[profile.release]
opt-level = "z"        # Оптимизация по размеру
lto = true             # Link-Time Optimization
codegen-units = 1      # Максимальная плотность кода
panic = "abort"        # Отключение стека паники для экономии килобайтов
strip = true           # Удаление символов отладки
```

### 2. Модели данных (`tile.rs`, `grid.rs`)
- **Типы сторон (EdgeType)**:
  `Field` (0), `Road` (1), `City` (2), `Water` (3), `RiverMouth` (4).
- **Тайл (Tile)**:
  Представляется 64-битным битовым полем (`u64`) либо компактной структурой:
  - 6 граней для гекса (Hex) или 4 грани для квадрата (Square).
  - Центр тайла: перекресток, монастырь, городское ядро, щит (герб).
  - Вращение: 0..5 (поворот на 60°) или 0..3 (на 90°).
- **Сетка стола (Board)**:
  - Пространственная хеш-таблица `HashMap<(i16, i16), PlacedTile>`.
  - Быстрый битовый кэш занятых ячеек для мгновенной проверки смежных соседей.

### 3. Алгоритмы поиска замкнутых контуров (`graph.rs`)
- **Дороги**: Обход графа в ширину (BFS) от размещенного тайла по дорожным ребрам до терминаторов (монастырь, городские ворота, перекресток, деревня или тупик). Если оба конца замкнуты — дорога завершена.
- **Города**: Поиск связных компонент замкнутого периметра городских стен. Очки начисляются за число плиток города + удвоенные очки за гербы/щиты.
- **Монастыри**: Проверка 8 смежных соседей вокруг плитки монастыря. 9 очков при заполнении всех 8 ячеек.
- **Правило большинства миплов**:
  Подсчет количества выставленных миплов каждого игрока на завершенном объекте. Очки забирает игрок с наибольшим числом миплов (при ничьей очки получают оба).

### 4. Интеллект бота (`bot/mcts.rs`)
- Бот оценивает:
  1. Немедленно получаемые очки.
  2. Завершение чужих объектов (блокировка ходов соперника, невозможность закрыть город).
  3. Сохранение миплов в резерве (штраф за слив последнего мипла в начале партии).
  4. Потенциал будущего расширения поля.
- **Уровни сложности**:
  - `Легкий` (Novice): жадный выбор хода с максимальным текущим приростом очков.
  - `Опытный` (Skilled): MCTS с 500 симуляциями (5–10 мс), оценка позиционного преимущества.
  - `Гроссмейстер` (Grandmaster): MCTS с 2000 симуляциями (15–20 мс) + эвристика блокировки городов соперника.

## 🌉 Мост JavaScript ⟷ WebAssembly (`src/engine/hybridEngine.js`)

```javascript
// src/engine/hybridEngine.js
// Прозрачный гибридный фасад: Wasm (Rust) с автоматическим JS-фоллбэком

let wasmInstance = null;
let isWasmLoaded = false;

export async function initHybridEngine() {
  if (isWasmLoaded) return true;
  try {
    // В Android WebView Wasm подгружается из встроенного Base64/TypedArray
    const wasmModule = await import('../wasm/tiletopia_core.js');
    await wasmModule.default();
    if (wasmModule.wasm_core_init()) {
      wasmInstance = wasmModule;
      isWasmLoaded = true;
      console.log('🦀 Tiletopia Rust WebAssembly Engine активирован!');
      return true;
    }
  } catch (err) {
    console.warn('⚡ WebAssembly недоступен, используется JS-ядро:', err.message);
  }
  isWasmLoaded = false;
  return false;
}

export function isRustActive() {
  return isWasmLoaded;
}

export function decideBotMove(board, drawnTile, botId, difficulty) {
  if (isWasmLoaded && wasmInstance) {
    try {
      const boardJson = JSON.stringify(board);
      const resJson = wasmInstance.bot_decide_move(boardJson, drawnTile.id, botId, difficulty, 30);
      return JSON.parse(resJson);
    } catch (err) {
      console.error('Ошибка Rust Wasm бота, переключение на JS:', err);
    }
  }
  // Fallback: вызов классического JS-бота
  return PG.engine.jsBot.decide(board, drawnTile, botId, difficulty);
}
```

## 🛠️ Скрипт сборки Wasm (`tools/build_wasm.py`)

Скрипт выполняет:
1. `cargo build --target wasm32-unknown-unknown --release` внутри `crates/tiletopia-core`.
2. Запуск `wasm-bindgen` для генерации JS-обвязки.
3. Оптимизацию бинарника через `wasm-opt -Oz` (Google Binaryen).
4. Преобразование `.wasm` в `src/wasm/tiletopia_core_embedded.js` (Base64 TypedArray) для гарантированной работы внутри Android WebView по `file:///android_asset/`.
5. Валидацию лимита размера бинарника (assert size < 60 KB).
