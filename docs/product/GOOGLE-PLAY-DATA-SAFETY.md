# Анкета Google Play «Безопасность данных» для Tiletopia

Рабочий черновик по коду версии 298 на 21 ноября 2026 года. Сверить ответы с итоговым Play AAB, действующей конфигурацией Firebase и опубликованными страницами до подачи. У одного пакета Google Play общая декларация для распространяемых версий и регионов. [Правила Data Safety](https://support.google.com/googleplay/android-developer/answer/10787469) · [Сбор данных SDK Firebase](https://firebase.google.com/docs/android/play-data-disclosure)

## Ссылки и основные ответы

- Политика конфиденциальности. [Русский](https://crownfall90-dot.github.io/TileTopia/privacy.html) · [English](https://crownfall90-dot.github.io/TileTopia/privacy-en.html)
- Веб-запрос на удаление. Подтвердить, что разработчик получает и может обработать письма на `puzzlegrad@gmail.com`. [Страница удаления](https://crownfall90-dot.github.io/TileTopia/delete-account.html)

| Поле анкеты | Рабочий ответ |
| --- | --- |
| Приложение собирает или передаёт данные | **Да**, используются Firebase Authentication, Realtime Database, Cloud Messaging, Analytics и Crashlytics |
| Данные шифруются при передаче | **Да** после проверки всех сетевых потоков итоговой сборки, включая SDK и WebView. Запросы клиента к Firebase используют HTTPS |
| Способы создания аккаунта | **Имя пользователя и пароль** (почта и пароль), **OAuth** (Google). Гостевой Firebase UID также возникает при обращении к облачным функциям. Сверить его с актуальными вариантами формы |
| Запрос на удаление аккаунта | В игре «Настройки → Аккаунт и данные → Удалить аккаунт и данные» и [публичная страница запроса](https://crownfall90-dot.github.io/TileTopia/delete-account.html). Перед подачей проверить оба пути и связанные данные |
| Запрос на частичное удаление данных без удаления аккаунта | Подтвердить ручной процесс по опубликованной политике. Выключение статистики останавливает будущую отправку и очищает локальные счётчики. Для ранее отправленных записей нужна отдельная проверка |

## Какие данные собираются

Для каждого типа оценить все места сбора, цели, сроки и получателей. Исключение Play для обработки поставщиком применяется, если он обрабатывает данные от имени разработчика. Для Analytics проверить условия и настройки обмена данными, для публичных профилей и игровых сообщений — применимость исключения для ожидаемой передачи по действию пользователя. [Определения Google Play](https://support.google.com/googleplay/android-developer/answer/10787469)

| Тип | Сбор и цели |
| --- | --- |
| Личная информация → Адрес электронной почты | При сохранении профиля по почте или через Google. Управление аккаунтом и вход |
| Личная информация → Имена | Никнейм при создании профиля. Отображение профиля, рейтинга и участников игр |
| Личная информация → Идентификаторы пользователя | Firebase UID, включая гостевой. Работа игры, управление аккаунтом и защита от злоупотреблений |
| Сообщения → Другие сообщения в приложении | Предустановленные реплики и реакции в комнате. Сюда же сверить отзывы, если отправляемый текст классифицируется как сообщение. Работа игры |
| Действия в приложении → Другой пользовательский контент | Проверить пользовательские статусы, тексты предложений и жалоб по определению Play. Работа игры и модерация |
| Действия в приложении → Другие действия | Ходы, онлайн-партии и игровой прогресс. Работа игры |
| Действия в приложении → Взаимодействие с приложением | События Analytics и дневные счётчики экранов, кнопок и действий собираются после включения «Статистики» для аналитики. Записи `/usage/{day}/{uid}` связаны с UID. Прежде чем выбрать «Необязательно», сверить остальные потоки этой категории |
| Информация о приложении и его производительности → Отчёты о сбоях и диагностика | Crashlytics и технические журналы для диагностики. Crashlytics и необходимые журналы работают независимо от согласия на статистику |
| Идентификаторы устройства или другие идентификаторы | Токены FCM, идентификаторы установки и экземпляра приложения. Уведомления, диагностика и аналитика. Проверить автоматическую регистрацию SDK при отказе от системного разрешения на уведомления |
| Местоположение → Приблизительное | Google Analytics может определять город и регион по IP. Проверить параметры потока и наполнение отчётов. Если собирается, указать приблизительное местоположение для аналитики и синхронизировать политику и уведомление о статистике. [География в Analytics](https://support.google.com/analytics/answer/12017362) · [Определение в Play](https://support.google.com/googleplay/android-developer/answer/10787469) |
| Контакты | Сверить внутриигровые связи друзей с определением Play, которое включает социальный граф. Игра не запрашивает системную адресную книгу. [Определение в Play](https://support.google.com/googleplay/android-developer/answer/10787469) |

Список блокировок версии 298 хранится на устройстве. При блокировке приложение может удалить приглашение из облачного входящего списка. Учесть событийную статистику интерфейса при включённом согласии. В итоговом манифесте проверить отсутствие разрешения `AD_ID`. Фотографии, файлы, звук микрофона, платёжные и медицинские данные для работы игры не требуются.

Клиент отправляет в `/presence` модель и размер экрана устройства, версию и технические показатели активности с момента гостевого входа. Правила в репозитории разрешают чтение этого узла всем авторизованным пользователям. Сверить действующие правила и перед подачей оставить в доступном другим игрокам узле только поля, нужные им для игры. Указать фактические цели технической аналитики и отдельно проверить её сбор при выключенной «Статистике».

## Удаление и хранение перед подачей

1. На изолированной базе создать гостя и сохранённый аккаунт, заполнить связанные данные, согласиться на статистику и проверить удаление из игры и через веб-запрос. Проверить результат удаления Firebase Auth и связанных записей, включая данные комнаты, связи друзей, журналы, счётчики `/usage/{day}/{uid}` и историю в резервных копиях.
2. Клиент выполняет проверяемое удаление доступных данных, включая обе таблицы рейтинга и дневные записи `/usage` за срок хранения. Сессию и локальные данные очищает после ответа Firebase Auth. Данные других участников, диагностические записи и резервные копии требуют отдельной обработки владельцем. Счётчикам `/usage` нужна плановая очистка за пределами срока хранения. Перед подачей воспроизвести сбой сети и отказ в доступе на изолированной базе, затем проверить повтор запроса. [Требования Google Play](https://support.google.com/googleplay/android-developer/answer/13327111)
3. Сверить опубликованные правила Firebase, работу очистки и резервного копирования, сроки Analytics и Crashlytics, публичные страницы и контакт разработчика. Сроки хранения и возможные исключения в анкете и политике должны соответствовать фактическому процессу.
